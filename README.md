# 삼국시대 역사 마블 온라인 (교실용 시범판)

## 파일
- `index.html` : 게임 화면
- `app.js` : 실시간 게임, 문제 제출·승인 기능
- `questions.js` : 나라별 6개씩 총 24문제 기본 자료
- `map.jpg` : 사용자가 제공한 원본 역사 지도
- `firebase-config.js` : **직접 Firebase 웹 앱 설정을 넣어야 함**
- `database.rules.json` : Firebase Realtime Database 규칙 예시

## 1. Firebase 설정
1. https://console.firebase.google.com 에서 새 프로젝트 생성.
2. 프로젝트 설정(톱니바퀴) → 내 앱 → 웹 앱 등록 → `firebaseConfig` 복사.
3. `firebase-config.js` 파일에서 `PASTE_...` 값들을 실제 설정값으로 교체.
4. 빌드 → Authentication → 시작하기 → 로그인 방법 → **익명(Anonymous)** 사용 설정.
5. 빌드 → Realtime Database → 데이터베이스 만들기 → 적절한 지역 선택 → 잠금 모드.
6. Realtime Database → 규칙(Rules)에 `database.rules.json`의 내용을 붙여넣고 게시.
7. Firebase 웹 설정의 `databaseURL`이 실제 Realtime Database URL과 일치하는지 확인.

## 2. GitHub Pages 배포
1. https://github.com 에 로그인 후 오른쪽 상단 `+` → New repository.
2. 저장소 이름 예: `history-marble`; Public으로 생성 (Pages 무료 공개 배포에 적합).
3. `Add file` → `Upload files` → 이 폴더의 **6개 파일을 모두** 업로드 → Commit changes.
4. Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, Folder: `/(root)` → Save.
5. 몇 분 후 `https://사용자아이디.github.io/history-marble/` 에서 접속.
6. Firebase 콘솔 → Authentication → Settings → Authorized domains에 `사용자아이디.github.io`를 추가 (기본 제공되지 않는 경우).

## 3. 교실에서 플레이 (동시 참여판 · 5학년 4~5팀 × 4명 기준)
- 교사: `교사: 새 방 설정`에서 시대·팀 수·팀 이름, **문제 시간(30초 기본·45·60초)** 과 **결과 표시 시간(4초 기본·3·6·8초)** 을 고른 뒤 `교사: 새 방 만들기`. 학생 접속 QR은 교사 화면에만 보입니다.
- 학생: 별명·팀 선택 → 방 코드 입력 → `학생: 방 입장`. 학생 화면 맨 위에 우리 팀·💎 연구·내 역할·이번 대표가 보이고, 그 아래 문제, 작은 지도(좁은 화면에서는 접기 가능), 공사 칸이 차례로 나옵니다.
- **팀마다 말은 하나**(`game.positions`). 팀 안에서 대표(주사위 담당)가 팀 차례마다 입장 순서대로 돌아가며, 다른 친구는 📖 읽기·근거, ✍️ 출제, 🔍 검토·꾸미기 역할을 함께 돌아가며 맡습니다(4명 미만 팀은 한 사람이 여러 역할).
- 시작 순서 주사위가 같으면 **다시 굴리지 않고 팀 번호 순서(1번 팀 먼저)** 로 한 번에 정합니다.

### 한 차례의 흐름
1. 대표가 주사위 → 팀 말 이동.
2. 빈 땅·다른 팀 땅(예전 출제 대기 땅 포함): **모든 팀이 같은 시대 문제**를 동시에 풉니다. 처음 8초는 혼자 생각(🤔), 그다음 팀 토의(💬), 마지막 10초는 확정(✅). 각 팀 대표만 최종 답을 누르고 마감 전까지 바꿀 수 있습니다. 다른 친구는 자기 화면에만 남는 연습 답을 고르고 근거를 말합니다. 교사는 도전 팀 대신 시연 답을 낼 수 있습니다.
3. **먼저 맞혀도 일찍 끝나지 않고** 공통 마감 시각에 한 번에 결과·해설이 공개됩니다. 도전 팀 정답 → 그 땅 LV1 차지 + 연구 1, 다른 팀 정답 → 연구 2. 오답·미제출은 패스이며 **벌점·쉬기 없음**.
4. 우리 땅 도착 → 연구 1 받고 곧바로 다음. 기회·사건 칸 → 카드.
5. 결과 카드는 다음 주사위 동안에도 남고, 정해 둔 결과 시간(기본 4초) 뒤 자동으로 다음 팀 차례가 됩니다.

### 💎 연구 포인트와 공사 (점수와 별개)
- 연구는 공사 재료일 뿐 **점수에 들어가지 않습니다**. 팀당 최대 20, 문제 하나당 한 번만 받습니다.
- 공사는 차례·단계와 상관없이 언제든 요청할 수 있고 현재 차례를 바꾸지 않습니다. 한 팀에 한 건씩만 검토합니다.
- **LV2 배움터**: 우리 팀 LV1 땅 + 우리 팀이 만든 4지선다 문제(보기 4개 서로 다름·정답·해설) → 같은 팀 친구 검토 → 교사 승인 → 연구 2 사용, 국력 +2. 승인 전까지는 원래 시대 문제를 쓰고, 승인되면 그 땅 문제로 쓰입니다(땅의 원래 주제 이름 유지).
- **LV3 상징**: LV2 땅 + 상징 그림(전망 탑·큰 성문·기념 정자) + 역사적 의미 한 줄(10~120자) → 검토·승인 → 연구 3 사용, 국력 +3. 땅 하나 공사 보너스는 최대 5점이며 반복 보너스는 없습니다.
- 기기 한 대로 하는 팀은 교사가 `선생님 검토+승인` 한 번으로 처리합니다(검토자는 교사로 기록). 작성자 본인은 검토할 수 없습니다.
- 땅을 빼앗기면 공사 단계와 땅 버전이 처음으로 돌아가고, 그 땅의 이전 요청은 이유와 함께 반려됩니다. 학생 초안은 기기에 거점별로 저장되어 **승인 확인을 받을 때까지 지워지지 않습니다**.
- 그림(`assets/*.svg`)은 놀이용 가상 건물이며 실제 유적 모습이나 새로운 역사 사실을 뜻하지 않습니다. 사진·이름 꾸미기는 선택이며 점수가 없습니다.
- 점수: 땅 국력 + 공사 보너스 + 출발점 통과 1회 1점 + 차지한 땅 1곳 1점 + 카드 점수. 점수판에 마우스를 올리면 항목별 계산이 보입니다.

## 시대·팀 설정 (2026-10 추가)
- 교사는 새 방을 만들 때 `교사: 새 방 설정`에서 시대(선사·삼국·남북국·고려·조선 전기·조선 후기·개항기·일제 강점기·광복과 대한민국 수립)와 팀 수(2~5, 기본 5)·팀 이름(1~20자, 중복 불가)을 고릅니다. 설정은 방의 `config`에 한 번만 저장되고 게임 중 바뀌지 않습니다.
- 팀 이름은 시대 주제로 붙인 **놀이용 이름**이며, 그 시대에 실제로 다섯 나라가 있었다는 뜻이 아닙니다.
- 삼국 시대 새 방은 기존 `questions.js` 24문제, 다른 시대는 `scenario-questions.js`의 시대별 24문제를 씁니다. 다른 시대의 기회·사건 카드 설명은 그 시대 문제 해설을 재사용하고, 점수 효과는 기존 숫자 그대로입니다.
- `config`가 없는 기존 방은 그대로 네 나라(고구려·백제·신라·가야)와 원래 규칙으로 동작합니다.
- 이전 방식(빈 땅에서 문제를 출제하면 땅을 자동으로 주던 규칙)은 없어졌습니다. 기존 방에 남은 출제 대기(`pendingClaims`·`completedQuestions`)는 **땅을 주지 않으며**, 교사 진행 현황의 `이전 출제 대기 정리` 버튼으로 안전하게 지울 수 있습니다. 예전 학생별 말(`studentTokens`)도 쓰지 않습니다.
- 주사위를 굴릴 차례인 학생 본인 화면에만 큰 `내 차례!` 알림이 뜹니다.

### ⚠️ Firebase 규칙 게시 필요
5팀 방에서 다섯 번째 팀(team 4)이 입장하려면 이 저장소의 `database.rules.json`을 Firebase 콘솔 → Realtime Database → 규칙에 **다시 게시**해야 합니다. 새 규칙은 `members/$uid/team`을 0~4 정수로 받고, 방에 올바른 `config/teamCount`(2~5)가 있으면 그보다 작아야 하며, 없으면(기존 방) 4보다 작아야 합니다. 이전 규칙 그대로면 다섯 번째 팀 학생은 "서버 규칙 때문에 입장하지 못했어요" 안내를 받고 입장되지 않습니다.

## 중요 제약
- Firebase 설정 전에는 온라인 플레이가 동작하지 않습니다. GitHub Pages는 정적 파일 배포만 담당합니다.
- 별도 서버가 없습니다. **교사 브라우저(진행 화면)가 유일한 진행자**로, 주사위·정산·자동 다음 차례·공사 승인을 게임 상태(`game`)에 트랜잭션으로 씁니다(학생은 `game`·땅 주인·연구·승인 문제를 직접 쓸 수 없음). 각 팀은 대표의 최종 답 하나만 채점됩니다.
- 교사 화면은 5초마다 진행 신호(`hostBeat`)를 보냅니다. 15초 넘게 신호가 없으면 학생 화면에 `선생님 진행 화면 연결을 기다리는 중`이 뜹니다. 그동안 마감 전에 낸 답과 공사 요청은 그대로 남고, 마감·다음 차례 시각은 절대 시각으로 저장되어 교사가 다시 접속하면 지난 마감을 한 번만 정산하고 이어서 진행합니다. 마감 뒤에 낸 답은 규칙에서 거절됩니다.
- 답과 해설이 실시간 DB에 저장되므로 개발자 도구로 볼 수 있습니다. 경쟁이 치열한 공식 대회용 보안은 아닙니다.
- 새 동시 참여판은 `database.rules.json`(학생 답: 내 uid·내 팀·지금 문제·마감 전, 공사 요청·친구 검토·승인 확인 경로)을 **다시 게시**해야 동작합니다.
- 확인 명령: `node --test test/*.test.mjs` (`test/classroom.test.mjs`는 가짜 시각·5팀×4명으로 정산·공사·보안 규칙을 실행해 봅니다).
- 익명 로그인은 브라우저별로 계정이 생성됩니다. 저장된 브라우저 데이터가 삭제되면 교사 권한을 잃을 수 있으니 수업 종료까지 같은 브라우저를 사용하세요.
- Firebase 요금 및 사용량을 확인하고, 수업 후 필요 없는 방 데이터는 콘솔에서 삭제하세요.
- 출제 문항은 학생 수준 및 역사적 정확성을 교사가 검토해야 합니다. 원본 지도는 특정 시점의 영토 표현입니다.

## 이번 버전의 복구·화면 보완
- 이전 버전에서 제한 시간 없이 풀던 문제는 교사 재접속 시 같은 문제로 제한 시간을 새로 설정합니다.
- 학생 화면은 문제·역할·연구·내 총점을 먼저 보여 주고 지도·전체 점수·접속 메뉴는 펼쳐 봅니다. 지난 해설도 다음 차례에는 접어서 보관합니다.
- 대표 기기가 끊기면 교사가 진행 현황에서 `문제 대표 바꾸기`로 같은 모둠의 다른 학생을 지정할 수 있습니다.
- 답안은 uid별 고정 슬롯에 두어 느린 삭제 요청이 다음 문제 답을 지우지 않게 했습니다. 거점별 초안은 학생·방별로 분리합니다.
- 릴리스 후 교사와 학생은 새로고침해서 새 버전으로 함께 접속해 주세요. 교사 화면은 수업 중 계속 켜 둡니다.
